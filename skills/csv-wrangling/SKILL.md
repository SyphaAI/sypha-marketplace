# CSV Wrangling with qsv

## Standard Workflow Order

When working with CSV data, always process it in this order:

0. **Setup (Cowork)** - Should relative paths fail to resolve, sync by calling `mcp__qsv__qsv_get_working_dir` and `mcp__qsv__qsv_set_working_dir`
1. **Index** - `index` (gives subsequent commands fast random access)
2. **Discover** - `sniff` (identifies format, encoding, delimiter) -> `headers` -> `count`
3. **Profile** - `stats --cardinality --stats-jsonl` (builds a cache that smart commands consume)
4. **Inspect** - `slice --len 5` (to preview rows), `frequency --frequency-jsonl` (value distributions, cached for reuse)
5. **Transform** - select, sort, dedup, rename, replace, search, sqlp, etc.
6. **Validate** - `validate` (checks against JSON Schema), `stats` (to confirm results)
7. **Export** - `tojsonl`, `table`, `mcp__qsv__qsv_to_parquet`, `to` (xlsx/sqlite/postgres/ods/datapackage)
8. **Document** - `describegpt --all` (produces an AI-generated Data Dictionary, Description & Tags)

## Tool Selection Matrix

| Task | Best Tool | Alternative | When to Use Alternative |
|------|-----------|-------------|------------------------|
| Select columns | `select` | `sqlp` | When computed columns are required |
| Filter rows | `search` | `sqlp` | For complex WHERE conditions |
| Sort data | `sort` | `sqlp` | When ORDER BY with LIMIT is needed |
| Remove duplicates | `dedup` | `sqlp` | When GROUP BY dedup is needed |
| Join two files | `joinp` | `join` | Use `join` when memory is constrained |
| Aggregate/GROUP BY | `sqlp` | `frequency` | `frequency` when simple counts suffice; `--frequency-jsonl` builds a cache |
| Column stats | `stats` | `moarstats` | Use `moarstats` when extended stats are needed |
| Find/replace | `replace` | `sqlp` | Use `sqlp` for conditional replace |
| Reshape wide->long | `transpose --long` | - | For complex reshaping, DuckDB UNPIVOT (external) |
| Reshape long->wide | `pivotp` | `sqlp` | For complex pivots |
| Concatenate files | `cat rows` | `cat rowskey` | When column orders differ |
| Sample rows | `sample` | `slice` | Use `slice` for positional ranges |
| Document dataset | `describegpt` | — | Data Dictionary, Description & Tags generated by AI |

## qsv Selection Syntax

This syntax applies to `select`, `search`, `sort`, `dedup`, `frequency`, and other commands:

| Syntax | Meaning | Example |
|--------|---------|---------|
| `name` | Column referenced by name | `select "City"` |
| `1` | Column referenced by 1-based index | `select 1` |
| `1,3,5` | Several columns | `select 1,3,5` |
| `1-5` | Inclusive range | `select 1-5` |
| `!col` | Omit a column | `select '!SSN'` |
| `!1-3` | Omit a range | `select '!1-3'` |
| `/regex/` | Match against column names | `select '/^price/'` |

## Common Pipeline Patterns

### Clean and Deduplicate
```
sniff -> index -> safenames -> fixlengths -> sqlp (TRIM) -> dedup -> validate
```

### Profile and Analyze
```
sniff -> index -> stats --cardinality --stats-jsonl -> read .stats.csv -> frequency (on key columns) -> sqlp (GROUP BY queries)
```
**Before writing SQL**: consult `.stats.csv` to find out column types, cardinality, nullcount, min/max, and sort order. Apply `frequency` to the columns you intend to GROUP BY or filter on. This lets you craft precise WHERE clauses, cast types correctly, and skip unnecessary COALESCE.

When SQL will be run repeatedly against a large CSV (> 10MB), think about converting it to Parquet: `sniff -> index -> stats -> to_parquet -> sqlp (using read_parquet())`. Note that `sqlp` is able to query CSV of any size directly.

### Join and Enrich
```
index (both files) -> stats (both) -> joinp -> select (keep needed columns) -> sort
```

### Profile and Document
```
sniff -> index -> stats --cardinality --stats-jsonl -> describegpt --all
```

### Convert and Export
```
excel (to CSV) -> index -> stats -> select -> tojsonl / qsv_to_parquet
```

### Batch Convert to Multiple Formats
```
excel (to CSV) -> index -> stats -> to xlsx report.xlsx
excel (to CSV) -> index -> stats -> to sqlite report.db
excel (to CSV) -> index -> stats -> to parquet parquet_output_dir
```

### File Integrity Verification
```
blake3 file.csv > checksums.b3 (before transfer) -> blake3 --check checksums.b3 (after transfer)
```

## Delimiter Handling

- CSV (`,`): the default; no flag required
- TSV (`\t`): pass `--delimiter '\t'` or use the `.tsv` file extension
- SSV (`;`): pass `--delimiter ';'` or use the `.ssv` file extension
- Auto-detection: set the `QSV_SNIFF_DELIMITER=1` environment variable

## Important Notes

- Column indices are **1-based** rather than 0-based
- The `--no-headers` flag alters behavior significantly - most commands expect headers to be present
- By default output is sent to stdout; write to a file with `--output file.csv`
- `.sz` (Snappy compressed) files are transparently auto-detected by many commands
- `cat rows` needs identical column order; for differing schemas, use `cat rowskey`
- `dedup` reads all data into memory and performs an internal sort; if the input is already sorted, pass the `--sorted` flag to switch on streaming mode with constant memory
- `sort` pulls the whole file into memory; for huge files, use `sqlp` with ORDER BY
- When running SQL repeatedly against a large CSV (> 10MB), converting to Parquet with `mcp__qsv__qsv_to_parquet` is worth considering for faster performance. Parquet works ONLY with `sqlp` and DuckDB — every other qsv command requires CSV/TSV/SSV input

## Tool Discovery

To find commands beyond the core tools loaded initially, use **`mcp__qsv__qsv_search_tools`**. In total there are 55 qsv skill-based commands spanning selection, filtering, transformation, aggregation, joining, validation, formatting, conversion, and more.

## Operational Notes

- **Timeout**: Operations time out after 10 minutes by default (adjustable via `QSV_MCP_OPERATION_TIMEOUT_MS`, max 30 min). Let operations run through to completion.
- **Memory**: Entire files are loaded into memory by `dedup`, `sort`, `reverse`, `table`, `transpose`, `pragmastat`, and `stats` (with extended stats). Prefer `extdedup`/`extsort` via `mcp__qsv__qsv_command` for files >1GB.
- **Cowork path architecture**: qsv executes on the HOST machine, so file paths have to be valid on the host. Always confirm with `mcp__qsv__qsv_get_working_dir`.
- **Sequential operations**: To avoid queuing delays, favor sequential qsv calls over parallel ones: index → stats → analysis.
- **Large files (>5GB)**: Allow `mcp__qsv__qsv_frequency` to finish. Fall back to `mcp__qsv__qsv_sqlp` with GROUP BY only when the server timeout is exceeded.
- **Context window**: Write outputs to files instead of returning them to chat. To inspect subsets, use `mcp__qsv__qsv_slice` or `mcp__qsv__qsv_sqlp` with LIMIT.
